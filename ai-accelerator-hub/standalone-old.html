Neo4j Graph — 15-level DAG · Traversal: 1 Cypher

Nodes: (:Level {code, idx, xpReward}) · Edges: (:Level)-[:REQUIRES]->(:Level) · User progress: (:User)-[:COMPLETED]->(:Level). canUnlock = transitive REQUIRES minus COMPLETED.

MATCH (l)-[:REQUIRES*]->(p) RETURN p
Cypher: prerequisites for L03
MATCH (l:Level {code:'L03_MEMORY'})
-[:REQUIRES*]->(p:Level)
RETURN p.code, p.title
Result: L02_PROMPT, L01_AWAKENING
canUnlock via graph
await canUnlockViaGraph(userId,'L02_PROMPT')
// {can: false, missing:['L01_AWAKENING']}
// Complete L01 → {can: true, missing:[]}

Leaderboard via graph
MATCH (u:User)-[:COMPLETED]->(l:Level)
WHERE u.tenantId='demo'
WITH u, sum(l.xpReward) AS xp
RETURN u.name, xp ORDER BY xp DESC LIMIT 5
Fallback when Redis absent — same result as ZSET
Hybrid model: Neo4j = graph (DAG, social, teams, recommendations) · Prisma/SQLite = transactional (xp_ledger hash chain, payments, audit). When NEO4J_URI absent, app falls back to relational level_prerequisites + progress — no fabricated data. See NEO4J_GUIDE.md + lib/neo4j.ts + lib/journey.ts.
