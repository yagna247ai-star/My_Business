# 📜 Sprint 0 Artifact: Data Contract & Solution Design

## 1. Executive Summary
Sprint 0 establishes the formal data specification, correlation identifier contract, and validation rules between **MyAppz Gen 2 CRM**, the **`uv`-managed FastAPI Gateway**, and **Smallest AI Voice Agents**.

---

## 2. Lead Identity Correlation Contract

Every voice call request and webhook payload MUST contain the following correlation payload:

```json
{
  "myappz_contact_id": "CNT_109283",
  "myappz_opportunity_id": "OPP_887211",
  "voice_session_id": "call_sai_7a8b9c123456",
  "phone": "+919876543210",
  "lead_source": "Facebook Meta Lead Gen",
  "dispatched_at": 1757074800.0
}
```

### Identity Rules
- `myappz_contact_id` (String, Required): Primary correlation key. Used to locate and update CRM contact records.
- `myappz_opportunity_id` (String, Optional): Associated deal ID for pipeline stage progression.
- `voice_session_id` (String, Required): Generated by Smallest AI API or Gateway (`call_sai_*`). Key for Redis SETNX lock `webhook:idempotency:{voice_session_id}`.
- `phone` (String, Required): E.164 formatted phone number. Checked against Redis set `dnc:blacklist`.

## 4. Pre-Call Validation Flow

```text
[Incoming Lead Outbound Request]
               │
               ▼
   Is phone in Redis `dnc:blacklist`?
        ├── YES ──► RETURN status: "Blocked_DNC"
        └── NO
               │
               ▼
   Can acquire Token Bucket token? (`rate_limit:smallest_ai`)
        ├── NO  ──► RETURN status: "Throttled_429"
        └── YES
               │
               ▼
   Generate `voice_session_id` & Dispatch to Smallest AI API
```
